# Clearframe repository guidance

Use [AGENTS.md](AGENTS.md) as the authoritative development instruction file. Read both [docs/clearframe-strategy.md](docs/clearframe-strategy.md) and [docs/project-context.md](docs/project-context.md) before proposing or implementing product-direction changes.

Essential constraints:

- The current installed product is a standalone, macOS-first SwiftUI + WebKit browser for ordinary users.
- Do not switch the current product to Chromium. The isolated CEF scaffold is only a future cross-platform/extension gate; it is not linked into the app and is not a full Chromium source fork.
- The root browser extension is a retained validation artifact, not the primary deliverable.
- Page assistance is local-first; optional provider use happens only after an explicit user action.
- Analyze Page must preserve source-language text across languages. Local mode is private extractive structuring, currently tested in English, Romanian, French, and Simplified Chinese; optional configured AI may provide deeper multilingual synthesis. Never claim uniform semantic quality or multilingual risk-detection parity.
- The AI home is a curated local directory of official links. Its sparse task badges, broad access labels, checked date, and source links follow [docs/ai-catalog-editorial.md](docs/ai-catalog-editorial.md); they are not universal/live rankings, Clearframe testing, partnerships, exact prices, affiliate ordering, or automatic page/prompt sharing.
- Never sell browsing history, add hidden ads, invent partnerships, or market heuristic risk signals as security verdicts.
- Prioritize extraction quality, measured calm performance, real-user clarity, Evidence Mode/Translate & Explain, and release security before broad feature expansion or monetization.
- The primary promise is “Clearframe makes the AI world simple for ordinary people.” Optimize the first minute around a human task, a small set of useful AI paths, and understandable page analysis. Do not present future exact Evidence Mode as delivered.
- Favor founder-led demos, real early testers, honest before/after examples, GitHub build notes, and observed learning. Do not recommend spam, fake traction, premature paid ads, or guaranteed-growth claims.
- Use [docs/go-to-market.md](docs/go-to-market.md) for launch decisions: the brand is global and English-first, while the first validation wedge is creators overwhelmed by AI. Treat activation, seven-day retention, and voluntary referrals as stronger evidence than views or follower counts.
- Preserve the `ClearframeCore` versus macOS UI/WebKit boundary and document material behavior or data-flow changes.
- Do not claim production signing, notarization, App Store readiness, password security, or security review without evidence.
- The Swift and JavaScript local-analysis implementations are intentionally separate but behaviorally equivalent. `macos/ClearframeBrowser/Tests/ClearframeCoreTests/Fixtures/local-analysis-contract.json` and `provider-contract.json` are the single source of truth for both, read by Swift through `Bundle.module` and by Node through a relative path. Change behavior in the contract first, then make both runtimes satisfy it; never edit one implementation alone.
- Local analysis selects stopwords by the page's declared language. Do not reintroduce a single merged multilingual stopword set — it silently suppresses ordinary English words such as “care” and “son.”
- Risk heuristics must stay context-aware. A bare mention of remote-desktop software is ordinary technical writing; a signal requires nearby action language plus pressure, support, account, security, or payment context.
- The repository is licensed under AGPL-3.0 ([LICENSE](LICENSE), verbatim upstream text). Do not relicense, add per-file license headers, or change the SPDX identifier in `package.json` without explicit user direction. Contribution terms (CLA or DCO) are still undecided; accepting outside patches before that is settled would compromise the maintainer's ability to offer separate commercial terms.
- Tracker blocking is real and must stay honest. It compiles a curated first-party domain list ([docs/content-blocking.md](docs/content-blocking.md)) through WebKit's `WKContentRuleList`. WebKit cannot report what it blocked, so the UI shows state only — never add per-page or running block counts, never import third-party blocklists without a separate licensing review, and never present blocking as a safety verdict.
- All chrome and surface colors come from `ClearframeTheme` in the `ClearframeBrowser` target; do not reintroduce scattered color literals. Semantic status colors (risk green/orange/red, failed-download red) stay semantic and are not part of the brand accent family.
- Site icons follow the `FaviconStore` policy: fetched only during an actual visit from the visited site's own origin, cached locally, memory-only in private tabs, wiped by the browsing-data reset, never a third-party icon service; unvisited hosts fall back to the local identity-color square.
- Folder icons ship as three selectable sets. Whether a tint reaches one is decided by the artwork, not by policy: Clearframe's own 104 are drawn in `currentColor` and are the only tintable set; never bake a colour into it. Clearframe's set stays the default because it is the only one containing the plain folder that every unset folder falls back to. The licensed sets carry their own colours, so the tint row is hidden for them rather than shown doing nothing, and their attribution must stay visible in the picker. Do not add GPL-licensed icon sets: one was added and withdrawn on Aug 19, 2026 because GPL copyleft covers the whole program, not only adaptations of the artwork, which would end the option of separate commercial terms. Prefer CC BY. Stickies (100) is Streamline artwork under CC BY 4.0; its single-lime `duo` form was withdrawn because that green fought the mint accent, and folders saved with it migrate to the surviving drawing rather than resetting. Emoji (1261) is EmojiOne v1 under CC BY-**SA** 4.0: bundling it is a collection, not an adaptation, so it does not put the app under share-alike — but modifying that artwork would, which would compromise any separate commercial terms. Treat it as read-only, never merge it into Clearframe's own set, and regenerate rather than hand-edit: `StickiesIconCatalogData.swift` and `EmojiOneIconCatalogData*.swift` come from the matching `scripts/import-*-icons.py`. `ClearframeTheme.siteIconSize` is the single size for every site icon and folder mark, set to match the toolbar's own icon row.
- The full-page bookmarks home is a per-tab start surface. New tabs and the Home button always open the AI guide; ⌘⌥B and the bar's All Bookmarks affordances open the bookmarks home.
- Automated coverage is not user validation. No observed-user session has been run yet, so never describe activation, retention, or usability as validated.

Do not revive rejected paths from old prototypes or conversations without explicit user direction and evidence. The root [README](README.md#documentation-index) links the strategy, product, architecture, privacy, research, run, and release-gap documents. The trusted upstream is `https://github.com/romanlucian/Ki-browser`; never rewrite it casually.
